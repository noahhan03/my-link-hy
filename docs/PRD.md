# MyLink (마이링크) — 1차 시연 PRD

> **문서 유형:** Product Requirements Document (제품 요구사항 정의서)  
> **버전:** v1.0 — Phase 1 (프로필 페이지 데모)  
> **작성일:** 2026-11-02  
> **상태:** 1차 구현 범위 확정 / 세부 디자인은 `design.md` 참조 대기

## 1. 문서 목적과 범위

마이링크(MyLink)는 사용자가 여러 웹사이트와 SNS 주소를 하나의 프로필에 모아 보여주는 링크 인 바이오(Link-in-bio) 서비스이다. 대상 사용자는 특정 직군에 한정하지 않은 **모든 사용자**이다.

이번 개발은 **서비스 제작 과정을 보여주는 단계별 시연**이 목적이다. 따라서 본 PRD에서 실제 구현할 대상은 **LocalStorage 기반 프로필 페이지와 해당 페이지에 필요한 최소한의 편집 기능**뿐이다.

### 1.1 이번 단계의 원칙

1. **프로필 페이지 우선:** 사용자에게 보이는 프로필 페이지(`/username`)를 먼저 구현한다.
2. **서버 없는 데모:** 백엔드, DB, 실인증 API 없이 브라우저의 LocalStorage에 저장한다.
3. **대시보드 미구현:** 프로필 편집을 위해 별도 관리자 대시보드를 만들지 않는다. 편집 기능은 프로필 페이지 내부의 간단한 편집 모드로 제공한다.
4. **통계 미구현:** 방문 수·클릭 수, 그래프, Mock 통계 생성 및 수집 로직은 만들지 않는다.
5. **단계별 확장:** 앞선 기획에서 확정된 로그인, 온보딩, 통계 등은 후속 단계의 계획으로만 남긴다.
6. **기술 선택 최소화:** 상태 관리 라이브러리는 Zustand로 확정했지만, React 프로젝트의 세부 프레임워크와 빌드 도구는 아직 정하지 않는다.

### 1.2 이번 단계 포함/제외 범위

| 구분 | 기능 | Phase 1 |
|---|---|---|
| 프로필 | username 설정, 표시 이름, 소개글, 프로필 사진 | **포함** |
| 프로필 | 미리 정의된 테마 선택 | **포함** |

| 저장 | LocalStorage 영속화 및 새로고침 복원 | **포함** |

## 2. 사용자와 핵심 시나리오

### 2.1 대상 사용자

- 개인 SNS, 웹사이트, 포트폴리오, 연락 채널 등의 링크를 모아 보여주고 싶은 모든 사용자
- 이번 데모에서는 **한 브라우저에 하나의 로컬 프로필**을 생성하여 체험한다. 실제 계정 시스템은 없다.

### 2.2 핵심 사용자 시나리오

1. 처음 방문한 사용자가 username과 기본 프로필 정보를 설정한다.
2. 자신의 프로필 주소인 `/username`에서 프로필을 확인한다.
3. 같은 페이지의 편집 모드에서 프로필 사진·표시 이름·소개글·테마를 변경한다.
4. 일반 링크 또는 SNS 링크를 추가하고 순서를 바꾼다.
5. 편집 중에는 미리보기에 즉시 반영되지만, **저장 버튼을 누르기 전에는 영구 저장되지 않는다.**
6. 저장하면 새로고침해도 변경된 내용이 유지된다.
7. 프로필 링크를 클릭하면 대상 페이지가 새 탭에서 열린다.
8. 프로필 URL을 복사하면 **다른 기기에서는 아직 이 프로필이 표시되지 않는다**는 데모 제한을 안내한다.

## 3. 라우팅 및 화면 구성

| 경로 | 화면 | 동작 |
|---|---|---|
| `/` | 최소 초기 설정 화면 | 로컬 프로필이 없으면 username 및 기본 프로필 생성 폼 표시. 있으면 `/username`으로 이동 |
| `/:username` | **프로필 페이지** | 저장된 프로필을 표시. 같은 브라우저에서는 편집 모드 진입 가능 |
| 알 수 없는 `/:username` | 프로필 없음 상태 | “프로필을 찾을 수 없습니다” 표시; 가능한 경우 내 프로필로 이동 안내 |

- `/`은 **랜딩 페이지가 아니라** 프로필 데모 진입에 필요한 최소 설정 화면이다.
- `/dashboard`, `/analytics`, `/login`, `/signup` 등 후속 기능용 화면은 현재 생성하지 않는다.
- 딥링크 및 새로고침 시 `/:username` 경로가 정상적으로 로드되도록 라우팅한다(배포 시 SPA fallback 고려).

### 3.1 프로필 페이지 보기 모드

위에서 아래 순서로 다음 요소를 표시한다.

1. 프로필 사진(사진 미등록 시 기본 아바타)
2. 표시 이름
3. 소개글(있는 경우)
4. SNS 플랫폼 전용 아이콘 목록(활성화된 항목만)
5. 일반 링크 버튼 목록(활성화된 항목만, 지정된 순서대로)
6. 프로필 URL 복사 버튼

프로필은 로그인 없이 열람 가능한 공개 페이지를 **형식상 구현**하지만, Phase 1에서는 같은 브라우저·동일 출처의 LocalStorage에 저장된 정보만 조회할 수 있다. 실제 접근 제어 기능은 제공하지 않는다.

### 3.2 프로필 페이지 편집 모드

- **데스크톱:** 왼쪽 편집 패널 + 오른쪽 모바일 크기의 실시간 미리보기
- **모바일:** `편집` / `미리보기` 탭 전환
- 편집 패널은 `프로필 정보`, `테마`, `일반 링크`, `SNS 링크` 영역으로 구성
- `저장`과 `취소` 버튼 제공; 변경 여부를 시각적으로 표시
- 저장하지 않은 변경사항이 있을 때 편집 종료 또는 페이지 이동 시 경고
- 별도의 관리자 대시보드, 통계 카드 또는 분석용 메뉴는 표시하지 않음

> Phase 1에 실제 인증이 없으므로 편집 모드 진입은 보안상 소유자 검증이 아니다. **해당 브라우저에서 동작하는 시연용 기능**으로 취급한다.

## 4. 기능별 상세 요구사항

요구사항 ID는 구현과 테스트에서 동일하게 사용한다.

### 4.1 초기 설정 및 username

| ID | 요구사항 | 우선순위 |
|---|---|---|
| PROF-01 | 프로필이 없는 경우 최초 진입 시 username을 설정할 수 있다. | Must |
| PROF-02 | username은 프로필 URL 경로(`/username`)로 사용한다. | Must |
| PROF-03 | username은 최초 설정 후 UI에서 변경할 수 없다. | Must |
| PROF-04 | `login`, `signup`, `dashboard`, `analytics` 등 예약 경로는 username으로 사용할 수 없다. | Must |
| PROF-05 | username은 URL에 안전한 영문 소문자, 숫자, `_`, `-`만 허용하는 것으로 **Phase 1 임시 규칙**을 적용한다. | Should |
| PROF-06 | 한 브라우저의 데모 데이터에서 한 개의 프로필만 만든다. | Must |

- 다중 계정 간 username 중복 검증은 실제 계정 시스템/DB 도입 이후의 요구사항이다.
- username 유효성 검사는 설정 직후 수행하고, 오류 시 구체적인 안내 문구를 보여준다.

### 4.2 프로필 정보 및 이미지

| ID | 요구사항 | 우선순위 |
|---|---|---|
| PROF-07 | 표시 이름과 소개글을 수정할 수 있다. | Must |
| PROF-08 | JPG, PNG, WebP 형식의 프로필 이미지를 업로드할 수 있다. | Must |
| PROF-09 | 업로드한 이미지가 편집 미리보기에 즉시 반영된다. | Must |
| PROF-10 | 이미지를 변경하거나 제거할 수 있으며, 이미지가 없으면 기본 아바타를 표시한다. | Must |
| PROF-11 | 이미지 파일은 클라이언트에서 축소·압축한 후 저장한다. 저장 용량 초과 시 오류를 안내한다. | Must |

- 실제 파일 서버 또는 외부 이미지 URL 입력 기능은 이번 단계에서 지원하지 않는다.
- 이미지 크기/압축 품질의 세부 수치는 구현 시 LocalStorage 용량을 기준으로 정하며, 원본 이미지를 그대로 저장하지 않는다.

### 4.3 프로필 테마

| ID | 요구사항 | 우선순위 |
|---|---|---|
| THEME-01 | 사전 정의된 테마 목록에서 하나를 선택할 수 있다. | Must |
| THEME-02 | 선택한 테마를 프로필 배경, 텍스트, 링크 버튼 등에 일관되게 적용한다. | Must |
| THEME-03 | 테마 선택 결과를 미리보기에 즉시 적용하고 저장 시 유지한다. | Must |

- 사용자별 색상 직접 편집, 폰트 개별 지정, 배경 이미지 업로드, 고급 레이아웃 편집은 구현하지 않는다.
- 테마의 색상·폰트·반경·간격 등 구체적인 디자인 토큰은 **`design.md`를 우선 참조**한다.

### 4.4 일반 링크 관리

| ID | 요구사항 | 우선순위 |
|---|---|---|
| LINK-01 | `제목`과 `URL`을 입력해 일반 링크를 추가할 수 있다. | Must |
| LINK-02 | 링크의 제목과 URL을 수정하고 링크를 삭제할 수 있다. | Must |
| LINK-03 | 링크 표시 순서를 변경할 수 있다. | Must |
| LINK-04 | 링크를 활성화/비활성화할 수 있고, 비활성 링크는 공개 프로필에 표시하지 않는다. | Must |
| LINK-05 | 링크 개수에 제품 차원의 고정 제한을 두지 않는다(브라우저 저장 한도는 예외). | Must |
| LINK-06 | 활성 링크 클릭 시 URL을 새 탭에서 연다. | Must |
| LINK-07 | URL은 `http:` 또는 `https:` 등 허용된 프로토콜인지 검사한다. 악성 스킴은 거부한다. | Must |
| LINK-08 | 링크 버튼은 기본적으로 **제목 중심의 텍스트 버튼**으로 표시한다. | Provisional |

> 링크 썸네일 사용 여부는 이전 질문에서 최종 확정되지 않았다. Phase 1은 구현 범위를 최소화하기 위해 **텍스트 버튼을 잠정 기본값**으로 사용하며, 확정 전에는 썸네일 업로드를 구현하지 않는다.

### 4.5 SNS 전용 링크

지원 플랫폼: **Instagram, YouTube, TikTok, X(Twitter), GitHub, LinkedIn, Facebook, Threads, Discord, Telegram, 카카오톡, 이메일** (총 12개)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| SNS-01 | 사용자가 위 플랫폼 중 하나를 선택해 주소를 등록할 수 있다. | Must |
| SNS-02 | 등록된 SNS 링크에 해당 플랫폼의 전용 아이콘을 표시한다. | Must |
| SNS-03 | SNS 링크를 추가·수정·삭제·순서 변경·활성화/비활성화할 수 있다. | Must |

- SNS 플랫폼 자동 감지와 외부 영상·음악 임베드는 제외한다.
- 일반 링크와 SNS 링크는 서로 다른 표시 영역을 사용한다.

## 5. 데이터 및 상태 관리 설계

### 5.1 기술적 결정

- **전역 상태 관리:** Zustand (**확정**)
- **UI 프레임워크 계열:** React 기반 (Zustand 선택에 따른 구현 전제)
- **구체 프레임워크/빌드 도구:** 미정 (예: Next.js와 Vite 중 아직 선택하지 않음)
- **영속 저장:** 브라우저 LocalStorage
- **서버/API/DB:** 없음
- **언어:** 한국어만 지원

### 5.2 Stage 1 Store 구성

| Store | 주요 데이터 | 영속화 |
|---|---|---|
| `useProfileStore` | 마지막으로 저장한 프로필·테마·링크 | LocalStorage |
| `useEditorStore` | 임시 Draft, 변경 여부, 편집 모드 | 메모리만 |

- `useAuthStore`, `useAnalyticsStore`는 **후속 단계에서** 추가한다. 이번 단계에서는 만들지 않는다.
- 상태 저장 정책: **초기 로드 시 LocalStorage → 저장된 Store 복원**, 편집 시 Draft만 변경, 저장 시 저장된 Store와 LocalStorage를 함께 갱신한다.
- Zustand의 persist 미들웨어를 사용한다면 Draft까지 자동 저장하지 않도록 주의한다.

### 5.3 LocalStorage 데이터 모델(초안)

키 예시: `mylink:profile:v1`

```json
{
  "schemaVersion": 1,
  "profile": {
    "username": "noah",
    "displayName": "Noah",
    "bio": "",
    "avatarDataUrl": null,
    "themeId": "default"
  },
  "links": [
    {
      "id": "link-1",
      "title": "내 블로그",
      "url": "https://example.com",
      "enabled": true,
      "order": 0
    }
  ],
  "socialLinks": [
    {
      "id": "social-1",
      "platform": "instagram",
      "url": "https://instagram.com/example",
      "enabled": true,
      "order": 0
    }
  ],
  "updatedAt": "2026-11-02T00:00:00.000Z"
}
```

> 위 JSON은 **필드 구조를 설명하는 예시**이며 실제 초기 사용자 데이터에 샘플 링크를 자동 추가하지 않는다. 신규 프로필의 `links`, `socialLinks`는 모두 `[]`로 시작한다.

### 5.4 LocalStorage 제약과 예외 처리

- 저장 가능한 용량은 브라우저에 따라 다르므로 이미지 압축과 저장 실패 처리가 필요하다.
- 사용자가 사이트 데이터를 지우거나 다른 기기·브라우저로 이동하면 로컬 데이터는 공유/복원되지 않는다.
- 읽기 오류 또는 스키마 불일치 시 앱이 중단되지 않도록 안전한 오류 상태를 표시한다.
- 사용자 입력과 외부 링크는 출력 시 안전하게 처리하고, 외부 링크에는 `target="_blank"`와 `rel="noopener noreferrer"`를 적용한다.
- Phase 1은 비밀번호와 OAuth 토큰을 수집하거나 저장하지 않는다.

## 6. UI/UX 요구사항

1. **반응형 웹:** 모바일과 데스크톱 모두 사용 가능해야 한다.
2. **쉬운 첫 진입:** 아직 프로필이 없으면 바로 최소 설정을 시작할 수 있어야 한다.
3. **빈 상태:** 최초 생성된 프로필은 일반 링크와 SNS 링크가 모두 0개이며, `첫 번째 링크 추가` 안내를 제공한다.
4. **편집과 보기 구분:** 편집 중인 값과 실제 저장된 값을 명확하게 구별한다.
5. **한국어 UI:** 버튼, 설명, 검증 메시지, 오류 상태를 한국어로 제공한다.
6. **접근성 기본:** 키보드 조작, 버튼의 접근 가능한 이름, 입력 오류 메시지, 충분한 텍스트 대비를 고려한다.
7. **디자인 소스:** 사용자가 지정한 `design.md`의 디자인 원칙을 우선한다. **현재 본 PRD 작성 시점에 파일 내용이 제공되지 않았으므로 특정 색상/타이포그래피/디자인 토큰을 임의 확정하지 않는다.**

## 7. 완료 기준 (Acceptance Criteria)

다음 항목이 모두 통과하면 Phase 1 데모를 완료한 것으로 본다.

- [ ] 첫 진입 시 username을 설정하고 프로필을 생성할 수 있다.
- [ ] 최초 생성 시 일반 링크·SNS 링크 목록이 비어 있다.
- [ ] `/:username`에서 프로필 사진, 이름, 소개글, 테마 및 활성 링크를 확인할 수 있다.
- [ ] 프로필 사진(JPG/PNG/WebP)을 업로드·교체·제거할 수 있다.
- [ ] 사전 정의된 테마를 선택하고 미리보기에 즉시 적용할 수 있다.
- [ ] 일반 링크와 12개 플랫폼의 SNS 링크를 추가·수정·삭제할 수 있다.
- [ ] 링크 순서를 바꾸거나 활성화 상태를 변경하면 미리보기에 반영된다.
- [ ] `취소`를 누르면 미저장 변경사항이 사라진다.
- [ ] `저장`을 누른 뒤 새로고침해도 모든 저장된 변경사항이 유지된다.
- [ ] 저장하지 않은 채 페이지를 이탈할 때 경고가 표시된다(브라우저가 허용하는 범위).
- [ ] 외부 링크가 새 탭에서 열리고 부적절한 URL이 거부된다.
- [ ] 프로필 URL 복사가 가능하고, 다른 기기에서는 열람할 수 없다는 제한이 안내된다.
- [ ] 모바일과 데스크톱에서 편집/미리보기 흐름이 정상 동작한다.
- [ ] 대시보드, 통계, 회원가입/로그인, Mock 분석 데이터 생성 로직이 Phase 1 결과물에 **없다**.

## 8. 구현 순서 (단계별 시연 계획)

**Step 1 — 프로필 렌더링**  
고정된 예시 객체로 프로필 보기 UI, 일반 링크 버튼, SNS 아이콘, 기본 테마와 반응형 레이아웃을 구현한다. (이 시점에는 LocalStorage에 의존하지 않아도 됨.)

**Step 2 — LocalStorage 연결 및 최초 프로필 생성**  
username과 기본 프로필을 생성하여 저장하고, 새로고침/경로 이동 시 로드한다. 링크 없는 상태를 처리한다.

**Step 3 — 프로필 편집**  
Zustand의 저장된 상태와 임시 Draft를 분리한다. 사진·소개글·테마 변경, 실시간 미리보기, 저장·취소를 구현한다.

**Step 4 — 링크 관리 및 안정화**  
일반 링크/SNS 추가·수정·삭제·순서 변경·활성화, 새 탭 이동, URL 복사, 입력 검증, 저장 오류 처리, 반응형 QA를 완성한다.

> 각 Step은 이전 Step이 동작하는 것을 확인한 뒤 다음으로 진행한다. Phase 1 완료 전까지 대시보드·통계 등의 기능을 선행 구현하지 않는다.

## 9. 후속 단계 계획 (이번 구현에 포함하지 않음)

### Phase 2 — 계정 및 정식 사용자 흐름
- 이메일 + 비밀번호와 Google/카카오 소셜 로그인 UI 및 Mock 인증
- LocalStorage 기반 신규 회원가입, 계정별 데이터 구분
- 회원가입 후 username → 프로필 사진/소개 → 테마 선택 온보딩
- 계정당 프로필 1개, username 최초 설정 후 변경 불가
- 로그인 상태 유지 및 로그아웃만 지원(계정 삭제·초기화는 우선 제외)
- 간단한 랜딩 페이지(로고, 소개, 로그인/회원가입, 프로필 예시)

### Phase 3 — 대시보드 및 통계
- 별도 대시보드, 링크 관리 UI 확장
- 프로필 조회수·전체 클릭 수·링크별 클릭 수
- 7일/30일 추이 그래프, 인기 링크 순위
- 초기 Mock 통계와 실제 브라우저 내 활동 기록 구분
- `useAuthStore`, `useAnalyticsStore` 도입 및 Store 간 연동

### Phase 4 — 실제 공유 서비스
- 백엔드, DB, 인증 연동
- 다른 기기에서도 조회 가능한 공개 `/username` 페이지
- 서버에서 username 중복 검증 및 영구 데이터 저장
- 실제 방문·클릭 통계 처리

> 이 Phase 구분은 **개발 순서를 설명하기 위한 임시 로드맵**이다. 각 후속 단계의 세부 PRD는 해당 단계에 착수할 때 별도로 작성한다.

## 10. 아직 확정되지 않은 사항

- **디자인 원본:** `design.md` 파일의 실제 내용은 아직 확인되지 않음. 구현 전 제공 필요.
- **일반 링크 썸네일:** 지원 여부 미확정. 현재 단계는 텍스트 버튼으로 잠정 처리.
- **React 기반 세부 기술 스택:** Next.js/Vite 등 미정. Zustand 사용은 확정.
- **세부 입력 제한:** 소개글 글자 수, 이미지 압축 목표치, 링크 제목 최대 길이 등은 구현 과정에서 검증 가능한 값으로 정할 예정.
